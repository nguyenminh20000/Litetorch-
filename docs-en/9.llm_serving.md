# 9. LLM Serving and Inference Optimization

LiteTorch integrates high-throughput inference features designed for production serving of Large Language Models.

---

## 9.1. PagedAttention & Block-based KV Cache

PagedAttention divides the KV Cache into fixed-sized blocks, preventing VRAM memory fragmentation:

```python
import litetorch as lt

device = lt.auto_device()

q = lt.Tensor.from_vector([0.1] * 128, [1, 1, 128], device, False)
k_cache = lt.Tensor.from_vector([0.2] * (16 * 16 * 128), [16, 16, 128], device, False)
v_cache = lt.Tensor.from_vector([0.3] * (16 * 16 * 128), [16, 16, 128], device, False)
block_tables = lt.Tensor.from_vector([0.0, 1.0], [1, 2], device, False)
context_lens = lt.Tensor.from_vector([32.0], [1], device, False)

out = lt.Ops.paged_attention(q, k_cache, v_cache, block_tables, context_lens, block_size=16)
print("PagedAttention output shape:", out.shape)
```

## 9.2. Continuous Batching & Serving Scheduler

Continuous batching operates at token-level granularity to dynamically inject incoming requests into ongoing batches:

```python
import litetorch as lt

scheduler = lt.nn.ServingScheduler(
    num_blocks=1024,
    block_size=16,
    max_num_seqs=64,
    max_num_batched_tokens=2048
)

req1 = lt.nn.Request(id=1, prompt=[101, 2054, 2003, 102], max_new_tokens=64)
req2 = lt.nn.Request(id=2, prompt=[101, 7592, 102], max_new_tokens=32)

scheduler.add_request(req1)
scheduler.add_request(req2)

active_requests = scheduler.step()
block_table_tensor = scheduler.get_block_table_tensor()
context_lens_tensor = scheduler.get_context_lens_tensor()
```

## 9.3. Prefix Caching

Caches reusable KV states for recurring system prompts:

```python
import litetorch as lt

cache = lt.nn.PrefixCache.get()
system_tokens = [1, 105, 200, 350]

k_data = lt.Tensor.from_vector([0.1] * 512, [1, 4, 128], lt.auto_device(), False)
v_data = lt.Tensor.from_vector([0.2] * 512, [1, 4, 128], lt.auto_device(), False)

cache.put(system_tokens, k_data, v_data)
cached_pair = cache.get_cache(system_tokens)
```

## 9.4. Speculative Decoding

Employs a lightweight draft model to generate candidate tokens and validates them in parallel using the main target model:

```python
import litetorch as lt

device = lt.auto_device()

draft_model = lt.nn.Sequential([
    lt.nn.Linear(256, 256, True),
    lt.nn.GELU(),
    lt.nn.Linear(256, 32000, False)
])
draft_model.to(device)

target_model = lt.nn.Sequential([
    lt.nn.Linear(256, 1024, True),
    lt.nn.GELU(),
    lt.nn.Linear(1024, 32000, False)
])
target_model.to(device)

engine = lt.nn.SpeculativeEngine(draft_model, target_model)
generated = engine.generate(prompt=[1, 45, 99], max_new_tokens=50, lookahead=4)
```

## 9.5. Medusa Multi-Head Engine

Appends auxiliary decoding heads to predict multiple subsequent tokens per forward pass without a standalone draft model:

```python
import litetorch as lt

device = lt.auto_device()

base_model = lt.nn.Sequential([
    lt.nn.Linear(512, 512, True),
    lt.nn.GELU(),
    lt.nn.Linear(512, 32000, False)
])
base_model.to(device)

head1 = lt.nn.MedusaHead(512, 32000)
head2 = lt.nn.MedusaHead(512, 32000)
head1.to(device)
head2.to(device)

medusa = lt.nn.MedusaEngine(base_model, [head1, head2])
tokens = medusa.generate(prompt=[10, 20, 30], max_new_tokens=40, lookahead=2)
```

## 9.6. Guided Decoding (Structured Outputs)

Constrains generative output to strictly adhere to regular expressions or grammars by applying logit masks during sampling:

```python
import litetorch as lt

vocab = ["{", "}", '"name"', ':', '"John"', '"age"', '25', ","]
decoder = lt.nn.GuidedDecoder(vocab)

logits = lt.Tensor.from_vector([1.0] * len(vocab), [1, len(vocab)], lt.auto_device(), False)
masked_logits = decoder.apply_mask(logits, prefix="{", target_pattern='\\{"name": "[a-zA-Z]+"\\}')
```
